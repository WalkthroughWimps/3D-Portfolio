# Notes drawing discoveries — October 25, 2026

The editor inspects only a completed human draw, pen path, or geometry edit. `drawing-discoveries.js` recognizes a loose circular head, a long outward shaft, three distinct roughly perpendicular teeth clustered near its far end on one side, and a clear step/jog in at least one outer tooth. The jog threshold is 8% of the tooth's outward rise (with a small absolute floor), so ordinary hand wobble remains acceptable but three straight teeth do not earn the key. Two teeth, even with a jog, do not earn it. It accepts separated strokes, continuous one-object Pencil or Pen keys, pen Bézier curves, ellipses, lines, and teeth assembled from joined line or thin-rectangle pieces; it permits small gaps, rotation, reflection, and scale. Closed square pen paths do not count as circles. The editor passes only visible objects from the changed shape's pane, so hidden groups, hidden panes and background art cannot complete a visible key. Each invocation gates by object metadata, samples at most 32 drawing objects total (31 neighbors plus the changed object) and at most 129 geometry points per object. Joining is limited to three pieces and 128 candidate chains. Recognition never runs during paint, render, load, import, Undo/Redo, or automatic gear tracing. It does not change source colors or geometry. Detection of imported shapes is available through an explicit pure function call for tests and future tools, but import never awards an item.

`key-clue.js` contains exactly the five visible user pencil strokes from `key.json`: ring (61 points), shaft (57), and three teeth (30, 23, 33). Its 204 coordinates are normalized to a unit-width square. It exports `keyCluePaths` as five ordered arrays of `[x,y]` pairs and `keyClueBounds` as `{width:1,height:<normalized>}`. It contains no hidden gear or background objects. Refs may render those paths as vector clue art without reading the 9 MB drawing file.

## Award contract for future inventory

Import `NOTE_AWARDS` and `noteAwards` from `drawing-discoveries.js`. Stable IDs are `refs-blank-plate` for the first circle and `refs-cabinet-key` for the key. `noteAwards.get()` returns all held `{id,persisted}` receipts. `noteAwards.subscribe(fn)` receives a new receipt once and returns an unsubscribe function. `noteAwards.award(id)` is idempotent and returns a receipt only for a newly awarded ID; `null` means already held or unknown. On local device storage failure, it returns `{persisted:false}` and keeps the receipt for this session. The editor shows that limitation in its accessible status. Each ID occupies its own monotonic localStorage key (`site.about.notes.award.<id>`) so one tab cannot overwrite the other award. Awarding rereads its key before emitting, handling a second tab's write even before its storage event arrives. The editor relays storage events into the store for same-origin cross-tab updates. A future inventory may get current receipts, then subscribe, and deduplicate by ID. No inventory panel, Refs lock, insertion behavior, drawing-document field, history entry, or export field is added here.

`detectNotesDiscovery(objects, changedId)` is the pure recognition API; it returns `{circle,key,examined}`. It does not write an award. The editor alone calls it on completed user changes. A consumer using it independently must decide whether the caller is a real authored gesture.

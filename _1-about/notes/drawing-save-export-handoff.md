# Notes drawing save, load, and export

The drawing panel now keeps named drawings in this browser's IndexedDB. Its dropdown lists saved names; **Save** updates the selected entry, and **Save as new** creates another entry. The existing `site.about.notes.v2` localStorage document remains a working canvas fallback for smaller drawings, alongside the separate IndexedDB working draft described below. The selected library identity is also kept in localStorage so Save targets the same entry after reload. If the working canvas differs when another drawing is opened, a separate recovery drawing is added to the dropdown before the switch. Undo can also return to the prior canvas. A failed recovery write stops the switch and reports the error.

**Load drawing file** accepts a bounded `.notes.json` editable backup, validates its document, adds it to the named library, and opens it. **Download editable file** backs up the current canvas in that same format. **Export PNG** downloads a square 1024 px image on `#46657f`, with the visible ordered artwork clipped to the circular glass. It uses the editor's artwork paint cache and current contrast/brightness appearance; hidden panes, hidden groups and shapes, selection outlines, snapping, and gear mechanics are omitted. No document mutation is needed for the export.

The `createDrawingEditor()` return value exposes `libraryReady`, `saveDrawing(asNew)`, `loadDrawing(id)`, `importDrawing(file)`, and `exportPngBlob()` for focused checks. Named storage is local to this browser and origin; the editable download is the portable backup. Storage denial, quota failure, bad imports, and PNG failure surface in the drawing panel status. Blob URLs and listeners are released on editor disposal.

## Large working drawings — October 22, 2026

The working canvas also saves to a separate `site.about.notes.working` IndexedDB database, including its selected named drawing ID and displayed name. The named drawings database opens at its existing version (2 or 3); only older databases missing the catalog store are upgraded. Edits queue one serialized IndexedDB writer; it snapshots the latest document, coalesces intervening edits, and drains pending writes on editor disposal or page hide. `flushAutosave()` on the editor awaits the current working save and returns whether the latest revision persisted. The old localStorage canvas remains a fallback for smaller drawings. A timestamp lets startup choose the newer working copy, and startup never replaces edits made while IndexedDB is opening. Large documents skip the localStorage write after serialization reaches three million characters; the drawing status reports success when the IndexedDB transaction completes. The **Reload saved** control reloads the current named entry and saves a separate recovery copy first if the working canvas differs.

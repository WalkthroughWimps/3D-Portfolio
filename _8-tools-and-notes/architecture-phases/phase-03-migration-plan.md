# Phase 3 file-by-file migration plan

Revision 1 | October 5, 2026 | Status: Instructions only; implementation starts only when the user selects Phase 4

Read `phase-03-architecture-decisions.md` (ADR sections 1-9) and all prior handoffs. New paths below are proposed, not files already implemented. Preserve the existing entry URLs and all inherited working-tree changes. Each numbered step is a review/rollback boundary; test its consumer before the next extraction. Do not combine dependency changes with scene logic changes.

## Phase 4 - Shared infrastructure only

1. **Snapshot and fixtures.** Re-read `tools/VALIDATION.md`, `tools/phase-02-correctness.test.mjs`, `tools/local-preferences.test.mjs`, and the Phase 3 handoff. Save working-tree state and raw preference fixtures without clearing personal browser data. Recover affected-route desktop/narrow/consent/reload evidence before runtime changes. Use a disposable browser profile for destructive storage tests. Keep every Phase 2 regression in `npm test`.
2. **Pure schema/storage.** Add `_7-shared-scripts/core/preferences.js`, `core/settings-schema.js`, `core/settings.js`, `core/lifecycle.js`; adapt `local-preferences.js` and `settings-store.js` as compatible facades. Add `tools/settings-store.test.mjs` with ADR precedence/failure/reset/cross-tab cases. Retain injected storage for deterministic Node tests. Snapshot fields/keys/events are defined by ADR section 3; no new authoritative duplicate settings blob.
3. **Settings/consent compatibility.** Adapt `_0-start/a11y.js`, `_7-shared-scripts/global-sync.js`, `scene-lighting-sync.js`, `site-config.js`, and `audio-consent.js`; add `core/consent.js`. Change only shared-setting call sites in `_0-start/start-page.js`, `_2-videos/videos.js`, `_4-games/games.js`, `_5-music/music-piano-controls.v2.js`, `shared-video-controls.js`, and `video-player-controls.js` to use facades. A one-line replacement of a direct read is allowed; extraction of their flows/scenes belongs to Phases 5/6. Preserve gains, drawing, prompt order, and event signatures. Audit direct writes so old same-tab writes cannot bypass notifications. Test direct entry with no saved preferences and conflicting saved preferences on every audio page.
4. **Assets.** Add `core/asset-policy.js` and `core/assets.js`; adapt `assets-config.js` without breaking exported/global helpers. Add `tools/assets-contract.test.mjs` covering ADR section 7. Keep image drawing/broken-resource helpers out of the pure resolver. Inventory `assetUrl` callers including media-catalog, games-layout, active music libraries, Videos bare asset keys, and Start local overrides. Convert ambiguity to `fromKey` or explicit page/site-relative resolution; retain local/CDN GLB paths and queries. Verify current soundfont rewrite before making any alleged fix.
5. **Header/bootstrap preparation.** Add `core/bootstrap.js`, `core/header.js`, `data/runtime-dependencies.json`, and `tools/prepare-site-html.mjs`. Keep the initial dependency manifest at existing per-page versions until step 7. Add write/check commands to `package.json` and document in `tools/VALIDATION.md`. Use marked regions in `index.html`, `_1-about/about.html`, `_2-videos/videos.html`, `_3-graphics/graphics.html`, `_4-games/games.html`, `_5-music/music.html`, `_6-docs/docs.html`; replace six duplicated header fetchers with initial markup sourced from `_7-shared-scripts/header.html`. Preserve Start's own landing navigation. Add thin mount hooks to entry scripts; no page internals extraction. Retain `js/site-utils.js` and attribution data. Generate classic `sw-asset-config.js`, update `sw.js` to consume it, and extend the worker harness without losing Phase 2 matching/offline cases. Check root/subpath header and asset configuration; test override limitations explicitly.
6. **Shared media/render boundaries.** Move pure seek/sync/pitch primitives from `shared-video-controls.js` into `media/transport.js`; turn `media-controller.js` into a facade over `media/controller.js`. Add additive subscribe/refresh/dispose and contract tests. Extract `applyScreenCanvasTexture`, `createTabletRaycaster`, `createScreenOverlay`, `createScreenOverlayPlane` and required generic helpers from `_2-videos/videos-tablet.js` to `scene/screen-surface.js`, with compatibility re-exports. Change `video-player-controls.js` shared imports to the new shared owner. Scaffold contracts for `media/controls-view.js`/`controls-input.js`; full drawing/input separation is Phase 5. Inspect transitive imports for cycles/page dependencies. Test model texture, overlay, raycast and redraw using current dependency versions first.
7. **Version consolidation.** Separately test the ADR candidate Three.js 0.159.0 on Start (0.158 baseline) and Docs (0.160 baseline), then all routes. Update the dependency manifest/import maps and direct imports in `_2-videos/videos.js`/`videos-tablet.js`, plus loader/decoder paths in Music/Docs and any discovered maintained consumers. Check `shared-glb-mouse-controls.js`, `tablet-focus.js`, Docs RoomEnvironment, CSS3D games, colors/lighting/GLBs. Do not choose a new version merely to remove a warning. If compatibility fails, keep this gate incomplete and document/review the amended candidate. Keep shader/material/camera constants unchanged.
8. **Opt-in storage infrastructure.** Add `storage/soundfont-store.js`, a reusable management view under that directory, `data/soundfont-packages.json` with version/digest/size metadata, and `tools/soundfont-store.test.mjs` (or equivalent meaningful browser/IDB contract harness). Prove selection-only storage, shared-bank references, version replacement, IDB transaction/reservation behavior, quota/eviction/removal/cancellation, and no eager decode. Test the actual Arachno and definitive-drums sizes. Keep 250,000,000 bytes visibly proposed until capacity results are recorded. UI must expose usage/removal when wired in Phase 6; this step does not change synthesis or add recording. Avoid persisting test banks in the user's regular profile.
9. **Shared checks and review.** Gate shared diagnostics through `debug/debug-loader.js` without losing inherited panel/filter behavior. Run `npm test`, lint delta, HTML preparation check, all affected route/settings/consent/playback checks and live CDN/worker checks. Obtain the Phase 4-required separate Astra/High review and resolve material findings. Report inaccessible evidence as incomplete for the relevant gate. Pass actual API signatures, wrappers, schema defaults, generated-region rules and manifest/storage version to Phases 5/6, update future instructions/PDFs, write handoff, and stop.

**Phase 4 exclusions:** no Start camera/controller extraction, Videos content/preview rewrite, Games embedding overhaul, music synthesis/scheduler extraction, full recording feature, cosmetic redesign, broad lint cleanup, or legacy file deletion. Thin integration is required so new infrastructure is exercised by real consumers, rather than left unused.

## Phase 5 - Start, Videos, then Games

1. **Start first.** Keep `_0-start/start-page.js` as entry. Extract, in order, `start/settings-flow.js` (prompts/preferences), `start/controller-scene.js` (model/material ownership), `start/camera-flow.js` (reuse existing `camera-transition.js`), `start/media-calibration.js`, and `start/accessible-controls.js`; all are proposed paths under `_0-start/`. Keep `_0-start/a11y.js` only as the Phase 4 compatibility facade. Move page diagnostics through debug integration, preserve animation/audio prompt sequence, fallback, slider/gain values and inherited filters. Recover and compare baseline screenshots before camera/material changes; record the lighting fallback issue without silently changing appearance. Pass reload/keyboard/reduced-motion/denial/mount-dispose checks before Videos.
2. **Videos second.** Keep `_2-videos/videos.js` as entry; use the real Phase 4 controller/surface APIs through `videos-video-adapter.js`. Split shared `video-player-controls.js`/`shared-video-controls.js` drawing and input into the Phase 4 proposed `media/controls-view.js` and `media/controls-input.js`, retaining facades. Move page orchestration into `_2-videos/video-session.js` and page content/preview selection into `_2-videos/preview-controller.js` around existing `preview-segments.js`. Keep `videos-tablet.js` and `tablet-focus.js` owning geometry/placement/transitions. Preserve thumb previews, pointer/keyboard controls, volume/mute/rate/pitch/sync, custom seek ownership and consent. Test active-video replacement and teardown before Games.
3. **Games third.** Keep `_4-games/games.js` as entry; extract `_4-games/game-scene.js`, `game-reel.js`, `game-session.js`, and `game-camera.js` in that order around existing `games-layout.js`, `games-video-adapter.js`, and `game-audio-bridge.js`. Keep generated game files external and bridge input/audio intact. Preserve Home/End redraw/bounds/audio sync and J/L/arrows; disable media actions in nonvideo mode. Verify iframe/game input focus, keyboard return, CSS3D placement, consent and teardown.
4. **Close Phase 5.** Remove duplicated ownership only after all call sites use the new owner. Do not remove old export facades still used by Music or alternatives. Run each page's baseline plus cross-page media regressions, collect resource cleanup evidence, document remaining lint and presentation work, update future instructions/PDFs, hand off stable adapters to Phase 6, and stop.

## Phase 6 - Music only

1. **Confirm active entry and capture baseline.** Start from `_5-music/music.html`, `music.js`, `music-piano-controls.v2.js`, `music-tablet.js`, and `music-transcription.js`. The active v2 query remains part of the entry until deliberately versioned. Inventory state/clock ownership, synth backend capability and file versions, mixer/trim keys, reference recordings and cold/warm/first-note timings. Define measured timing tolerances before extraction; do not treat Phase 1 missing measurements as zero cost.
2. **Catalog/loading.** Extract `_5-music/instruments/catalog.js`, then `instruments/loader.js` from active v2. Bind catalog IDs to `data/soundfont-packages.json`; integrate Phase 4 disk-store read/save/removal UI with explicit user selections. Keep current network/backend fallback order and validate soundfont JS package execution/CSP and SF2 ArrayBuffer loading from saved bytes. Check attribution/version integrity; prove one shared bank per package version. Playing or preparation must not opt the user into saving.
3. **Audio and mix.** Extract `_5-music/audio/session.js` (AudioContext, nodes, voice ownership), `audio/mixer.js` (existing master/category/autogain ranges), then `audio/midi-scheduler.js` (audio-clock scheduling). Preserve current gain boost, sustain/release/overlap, percussion channels, bank/program selection, switching and sync sign. Migrate `audioLeadTrimMs` only after documenting its separate semantics. Keep transcription's public boundary and existing recording behavior; do not expand recording scope.
4. **Scene/input/UI.** Extract `_5-music/scene/piano-scene.js`, `input/piano-input.js` (hit testing/keyboard), and `ui/music-panels.js`, using shared media adapters where semantics match. Retain `music-tablet.js` page geometry. Move history diagnostics under debug; add scope cleanup, late-result cancellation, MIDI/all-notes-off, timers, buffer leases and GPU disposal. No stuck notes on blur/teardown/consent change.
5. **Preparation API.** Add `_5-music/instruments/preparation.js` implementing ADR `prepareForRecording`, progress, cancellation, context/version invalidation, separate memory ledger and release leases. Validate the provisional 128 MiB preparation budget with PCM/backend/peak-copy measurements; report unsupported multibank backends honestly. Measure network-cold, saved-raw, and decoded-ready behavior for representative per-instrument packages and SF2 banks. A recording UI/engine and an AudioWorklet rewrite remain outside this phase.
6. **Close Phase 6.** After each extraction check audio start/pause/seek, first note, sustain/release/overlap, rapid switching, MIDI, existing recording/transcription, consent and video sync against measured tolerances. Keep rollback points. Trace legacy alternatives but retain uncertain references. Report missing audio-device coverage, update Phase 7/8 documents/PDFs, write handoff, and stop.

## Phase 7 - Presentation and measured performance

1. Complete accessible icon names, landmarks, page titles/descriptions, and HTML alternatives. Validate the Phase 4 initial navigation; do not create a second header-delivery implementation.
2. Recover any remaining durable baseline screenshots with verified viewport dimensions. Test keyboard/focus/dialogs/reduced motion, narrow layouts, direct entry, denied sound, blocked storage, failed assets and unavailable WebGL.
3. Consolidate CSS tokens/components while comparing intentional visual changes, including the recorded lighting fallback behavior.
4. Measure load, long tasks, frame activity, media startup and retained resources before optimizing. Preserve audio clocks and active controls.
5. Repeat desktop/mobile/keyboard comparisons with browser/device/origin/cache conditions recorded.
6. Compare network-cold/disk-cached/memory-prepared instrument selection-to-ready and first-note timings; validate separate disk/RAM budgets, oversize banks, shared SF2, removal and eviction. Report supported limits rather than substituting file sizes for timings. Update Phase 8/PDF, hand off evidence, and stop.

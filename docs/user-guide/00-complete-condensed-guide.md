# Portfolio maintenance guide - condensed edition

## Start here

This is the complete short guide to the current site's major systems. It explains the first place to make a change and how to save it. The detailed chapters expand these instructions. The working site is still evolving; do not interpret an older handoff's test counts or screenshots as current acceptance.

Project folder: `C:/Dropbox/Resume Website`. Local preview: http://127.0.0.1:8878/. The public website is separate. Saving a local file, exporting settings or clicking Save to project does not publish it.

### The basic update routine

1. Identify the page and feature below. Try its existing Settings or Constructor control before editing code.
2. Back up private drawings/layouts through that feature's own export. A settings archive is not necessarily a content backup.
3. For code, find the active HTML entry and follow its imports. Keep the existing public path and persistent IDs.
4. Change one feature at a time. Preview it in a separate tab, preserving any tab with unsaved work.
5. Check the feature, keyboard operation, sound permission and Reduced motion as applicable. Save/export the intended data layer.
6. Publish only through a separately reviewed release workflow. This guide does not authorize a deployment.

## Where things live

- `_0-start` through `_6-docs`: page-specific source and local feature assets. Root `index.html` opens Start.
- `_7-shared-scripts`: shared interface, settings, input, media, panel assembly, storage and annotations.
- `debug`: the normal Settings/Constructor shell as well as diagnostics. Do not remove it from release just because of its name.
- `assets`: shared models, images, SVG, audio, documents, vendor code, annotations and selected-work art. Page-owned assets can also live beside their page.
- `games`: embedded game projects. `_4-games` is the arcade cabinet; Graphics' freeform boards are a third distinct system.
- `source-files`: editable originals and preparation recipes. Runtime exports are not always suitable editing masters.
- `Videos`, `Renders`, `music`, `midi`, `soundfonts`: local copies of externally hosted media families. Some required inputs are ignored by Git.
- `tools`: preview, import, export, conversion, packaging and validation commands. Some generators write several runtime files.
- `data`: catalogs/manifests. `docs`: the current reference and these editable guide chapters. `_8-tools-and-notes`: workflows, coordination rules and dated handoffs.
- `output` and `outputs`: retained evidence and deliverables. `tmp`: local intermediates. Do not delete them as a group without a retention review.

## Shared interface and settings

Open the gear for Settings. General owns Audio, Scene appearance, Header, Focused media, Accessibility, Transform resets and Points of interest. Page/face contexts hold specialist controls. Constructor is an authoring mode with additional controls where implemented. Debug is the separate left drawer.

Left-click a section heading to fold one section. Right-click a heading to toggle its context's sections. Introductory text should sit outside redundant outer folds. Some contexts use private transfer formats; use their own export/import rather than copying form values.

For a new shared setting, update `_7-shared-scripts/core/settings-schema.js`, its UI binding and the actual feature subscriber. `core/settings.js` stores state; `core/settings-controls.js` binds controls; `debug/panel-shell.js` builds common tabs. A schema default affects fresh/default state; an existing browser preference can override it. Do not reset all storage just to see a new default.

For header/nav links, edit `_7-shared-scripts/header.html`. `core/header.js`, `template.css` and `colors.css` handle behavior and appearance. Marked HTML/header/import-map regions are generated by `tools/prepare-site-html.mjs`; update the source, generate in a coordinated window, then check the output. Do not hand-edit only one generated copy.

For Page summary text and points of interest, inspect `core/page-summary.js` and the page's `registerPageSummaryPoints` callback. Use real page actions instead of simulated keyboard events. Selected work and resume/contact content spans `core/selected-work.js`, header markup and `_0-start/start/project-overlays.js`.

Shared mouse transforms/reset behavior belongs to `shared-glb-mouse-controls.js`; page adapters still own exceptions. `core/panel-viewport.js` accounts for Settings/Debug space. `core/presentation-ui.js` controls focused-media UI movement/layering. Preserve usable Back/gear controls.

## Start page

Active entry: `index.html` -> `_0-start/start-page.js`. Supporting modules are under `_0-start/start/` and styles in `start-page.css`.

To change welcome text or native markup, find the visible phrase in `index.html`. To change controller/setup behavior, follow the corresponding handler in `start-page.js` and its helper. Active entry: `_1-about/about.html` -> `about.js`; `faces/index.js` registers faces. Page summary jumps to a face. Settings has Cube and individual face contexts. Fish's compatible internal ID remains `about`; Oddio is `odd`; the Cube settings context uses `faces`.

- Refs: `faces/refs/face.js`, cabinet/door/editor modules and its README. Separate cabinet geometry, artwork sources and saved layouts when changing them.
- Skills: `faces/skills/face.js` and neighboring `BeanBag*` modules. Visuals, supply, throwing and sounds have separate owners; shared panel construction is in `panel-assembly`.

- Oddio: `faces/odd/face-runtime.js`, `deck.mjs`, `cloth-rig.js`, `pod-config.mjs`, `addon-layout-editor.js`. Constructor already moves permitted side panels and assigns supported actions to the two four-button panels. The 3D controls and accessible 2D deck share an engine. Extend their action bridge rather than creating duplicate transport state.
- Notes: `faces/notes/face.js` integrates the workspace in `_1-about/notes/notes-face.js`. Tools, layers, model, history, library/export and gear modules live under `notes/`. Drawings require their own content save/export; shared preferences are a separate layer.

For a face edit, preserve the host attach/update/suspend/resume/dispose contract. The host owns borrowed cube resources. Shared face layout/backing/travel changes require coordination with face owners. About's text fallback is in the HTML, `about.css` and `fallback-carousel.js`; it must navigate independently when the 3D module fails.

## Videos and shared player

## Music page

Active 3D entry: `_5-music/music.html` dynamically imports `music-piano-controls.v2.js`. `music.js` is supporting page code; older similarly named piano controllers are not the active 3D entry. `music-2d.html` is a separate piano/recorder route, not disposable duplication.

Use More for the instrument lists; Settings -> Music exposes the current gain, highlight, screen and icon-distribution controls. Instruments start at `instruments/catalog.js` and its loaders/backends. Track layout, timing, seek state and recorded volume have named helper modules alongside the active controller.

To update a song, find its track record, audio candidates, MIDI and video references together. Recorded media supplies soundtrack audio; MIDI drives notes/keys and timing. Do not repair recorded-track volume by changing only synthesized-note gain. Follow `_8-tools-and-notes/music-midi-workflow.md` and `source-files/music-midi/` for current preparation recipes.

Verify from a user gesture with sound allowed, then denied/muted; seek while playing and paused; check sustain/keys/notes, rate changes and return to the piano. Preserve each track's tempo map and calibration.

## Docs desk and library

Active entry: `_6-docs/docs.html` -> `docs-3d.js`. The document collection is `documents.json`; its editor and validator are in `library/editor.js` and `library/schema.js`.

To add/edit a PDF, image or presentation, open Docs Constructor and use Document, Source and cover, and Paper format and placement. Choose the appropriate type, set title/description/source and adjust size/position. Browser edits are drafts. On the local review site, use Save to project to write the reviewed manifest; local uploads use the loopback authoring server. Export the collection for a portable manifest backup. A manifest is not a copy of every uploaded binary.

Inline PowerPoint playback uses a permitted Microsoft embed/link; an uploaded PPTX is preserved as an original-file link rather than converted into that animated viewer. The current Document type also supports bounded local uploads of other office/text originals; consult `_6-docs/README.md` for formats and limits. Check hosted presentation permissions signed out. Desk geometry is `_6-docs/assets/desk.glb`, generated by `tools/export-docs-desk.py`. Its original and editable extracted blend are documented in `assets/README-desk.md` and `source-files/docs-desk-and-cabinet/README.md`.

Drawer interaction is in `desk-drawers.js`. Preserve the four Drawer node names and parent-local offset metadata when exporting a replacement. Texture detail depends on correct UV scale as well as image size. Current web color maps are capped at 1024px and supporting maps at 512px; avoid substituting the large authoring blend for the web GLB.

## Sticky notes and saving

General Constructor edits note text/appearance and exports/imports the note bundle. Shared owners are in `_7-shared-scripts/sticky-notes/`; each page supplies scene attachment behavior. Check current adapter availability before assuming every surface can be authored.

Published content is `assets/annotations/sticky-notes.json`. Browser drafts can override that whole bundle locally, while visitor read history is separate. A local edit does not publish. Export, review and deliberately update the project bundle. Stable surface IDs and anchor conventions are part of saved content; geometry replacement may require migration. Verify placement without accidental model actions, read/hide/show, reload and import/export.

## Preview, recovery and future maintenance

Run the existing `npm run review` from the repository root for local authoring preview. An already running server may be shared with other chats; do not kill it casually. Use `package.json` and `tools/VALIDATION.md` for maintained commands. Some tools generate source or package output rather than just inspect it.

For missing models, inspect the browser's first error and network path. Bare `three` errors point to import-map/module loading; missing local assets may be separate ignored inputs; valid files can still fail CORS or media decoding. For silent sound, inspect consent/mute/volume and the actual audio owner before changing files. Do not clear user storage as a generic fix.

Folder moves are deferred. Before a migration requiring quiet time, notify the human, coordinate active owners, map old/new paths and preserve public URLs, saved IDs, generators and packaging references. No uncertain file is approved for deletion merely because it lacks a direct import.

Remaining manual work: verify current UI paths and recipes in the browser; expand settings/asset indexes and screenshots; refresh chapters after ongoing page work. Separate site acceptance, architecture/refactor, keyboard/mobile/model and release phases remain in the maintained project plans.
